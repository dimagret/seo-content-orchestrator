## Why

PR #13 landed the rail boundary into `master` but stopped short of three
small but explicit obligations:

- the G4 canary owner-decision was verbal ("APPROVED G4 canary for
  job-…") but not yet anchored in the approval artifact section 11;
- `OperatorAttestation.accepted_at_utc` was accepted without bounds
  (a future timestamp would silently push an operator attestation into a
  later evidence window — exactly the kind of drift the rail is meant
  to prevent);
- the finalizer was callable only as a library, so a fresh operator
  session had to re-import `services/supervised_subscription` instead
  of running a single CLI verb that the rail boundary explicitly
  authorises.

This PR contains **no** provider HTTP, no Hermes proxy, no OAuth, no
publication, and no scope expansion beyond the three obligations above.
The supervised modules continue to import neither `httpx`, `requests`,
`socket`, `subprocess`, `urllib`, nor `webbrowser` — enforced by
`tests/unit/test_runner_cli.py::test_supervised_modules_import_no_transport_or_process_clients`.

## What this preserves (carried over from PR #12 / #13)

- same `gpt-5.6-terra via openai-codex` subscription model;
- same Hermes session context;
- frozen research/evidence snapshot;
- fixed structured prompt per stage;
- independent `critic` stage;
- deterministic fact/citation/style/schema checks;
- immutable local artifact;
- manual final review;
- the rail owns the operator-session lifecycle,
  `JobService` owns the SEO-job lifecycle, exactly two crossings
  (`QUEUED → RUNNING` in `prepare_supervised_packet`,
  `RUNNING → SUCCEEDED` in `SupervisedSubscriptionFinalizer.finalize`);
- `OPERATOR_RECOVERY_REQUIRED` and `CANCEL_REQUESTED` remain rail-only
  and never imply `FAILED_RETRYABLE` or `JobState.CANCELED` automatically;
- four stages, fixed order, `maximum_retries=0`.

## Security / privacy

- the AST-based guard test
  `test_supervised_modules_import_no_transport_or_process_clients`
  asserts that `supervised_rail.py` and
  `services/supervised_subscription.py` import none of
  `httpx`, `requests`, `socket`, `subprocess`, `urllib`, `webbrowser`;
- `OperatorAttestation` now rejects timestamps later than the local
  authoritative clock (or malformed `accepted_at_utc` strings),
  eliminating one class of silent attestation drift;
- `_read_private_json` (PR #12) continues to enforce `O_NOFOLLOW`,
  `0o600`, single-link, owner-uid match, metadata recheck before/after
  open and after read, and rejection of duplicate JSON keys and
  non-finite numbers;
- revision QA (PR #12) continues to reject credential-like text,
  forbidden artifact fields, sources absent from frozen evidence,
  malformed citations, and hidden-reasoning keys;
- `CANCEL_REQUESTED` continues to record `local_request_only=true` and
  `upstream_cancellation=false` and is not equivalent to upstream cancel;
- `request_cancel` does not transition `JobService` to `JobState.CANCELED`
  — that requires a separate explicit operator gate.

## Out-of-scope follow-up

- any consumer-Codex upgrade (durable idempotency, retrieve-after-crash,
  cancel) would change the verdict in
  `docs/superpowers/specs/2026-08-23-codex-lifecycle-evidence.md` and
  unlock a separate unattended-executor design.
